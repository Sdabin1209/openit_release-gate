# ADR-0012: 잡 출력은 실행 중에 자기 검사하고 /readyz는 시험에서만 검사한다

- 상태: 채택
- 날짜: 2026-10-29

## 맥락

계약 v2.2.1이 `GateJobResult`, `GateReadyz`, `GateExt`를 정했다. 이 영역이 쓰는 출력을 어디서 스키마로 검사할지 정해야 했다.

## 결정

- 잡 출력(`GateJobResult`)과 ext(`GateExt`)는 내기·쓰기 전에 실행 중 검사한다. 어긋나면 `INVALID_RECORD`로 막는다.
- `/readyz` 본문(`GateReadyz`)은 실행 중에 검사하지 않고 시험에서만 검사한다.
- 잡의 설정 오류는 code `INVALID_RECORD`, 종료 코드 1. 예기치 못한 예외는 code `UNAVAILABLE`, 종료 코드 75(D105, 재시도 가능).

## 왜

- 잡 출력은 스케줄러가 읽는 약속이고, 어긋난 줄을 ok로 내보내면 스케줄러가 잘못 판단한다. 틀린 출력을 내지 않는 쪽이 안전하다.
- `/readyz`는 컨테이너 준비 상태를 알리는 경로다. 자기 검사가 실패해 503이 되면 정상인 서비스가 멈춘 것으로 보인다. 헤드 결정(2026-10-29): 자기 검사 실패로 readyz가 멈추는 쪽이 더 나쁘다.
- 종료 코드는 계약 GateJobResult 설명의 표(UNAVAILABLE = 75, 그 밖의 실패 = 1)와 D105를 따른다.

## 검토한 대안과 버리는 이유

- `/readyz`도 실행 중 검사: 위 이유로 버린다.
- 예기치 못한 예외를 종료 코드 1: 일시적 장애를 스케줄러가 재시도하지 못한다. 버린다.

## 결과

얻는 것: 스케줄러가 읽는 줄은 항상 계약을 지킨다. 감수하는 것: `/readyz` 모양이 계약에서 어긋나는 것은 시험이 잡을 때까지 운영에서 드러나지 않는다.

## 되돌리는 조건

`/readyz` 어긋남이 시험을 빠져나간 사례가 생기면 로그만 남기는 실행 중 검사를 추가한다.
