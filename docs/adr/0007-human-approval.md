# ADR-0007: 합격 기준은 지표 비교(설정 아님), 최종은 사람 승인

- 상태: 채택 (D53)
- 날짜: 2026-10-28 (작성 시점의 코드·문서 기준. 결정 시점은 근거 항목에 적는다)

## 맥락

모델·문항 조합을 환자에게 내보내도 되는지의 기준. 브리프 초안은 임계치 통과였다.

## 결정

코드와 정책 파일에 합격 임계치를 두지 않는다. 평가는 model-lab이 `EvaluationReport`(합격선 없음)로 낸다. 게이트는 기술 호환과 보고서의 존재·형식만 검사하고, 승인 요청 보고서(`ReviewReport`)에 후보 대 활성 릴리스의 지표 비교를 담아 `release-approver`에게 보여 준다. PASS는 APPROVE 뒤에만 생긴다. 보고서 해시(`X-Openit-Report-Hash`)로 본 것과 결정 시점의 보고서가 다르면 409(STALE_REPORT).

## 왜 (따른 표준과 근거)

- 근거: D53, D30, 사용자 결정 O11(안전 지표 임계치는 사용자가 정한다). 임상·안전 기준을 임의로 정하지 않는다는 브리프 1절. '왜 사람인가': 환자 안전에 관한 출고 판단을 자동 임계치로 대체할 근거가 없다는 결정이다.
- 지표 비교를 승인 화면에 두는 이유: 사람이 판단할 재료를 같은 기준(활성 릴리스)으로 보게 하려는 것(design.md 4절). 값 판단은 하지 않는다.

## 검토한 대안과 버리는 이유

- 임계치 자동 통과: D53이 폐기. 버림.
- 완전 수동(보고서 없음): 승인자가 근거 없이 결정하게 된다. 버림.

## 결과

승인자 신원이 기록의 핵심이 된다(ADR-0005). 합격선 설정 파일은 없고 정책은 `gate_policy_version`만 남는다.

## 되돌리는 조건

O11 임계치가 사용자 결정으로 정해지면 '자동 검사 항목 추가'로 넣을 수 있으나 PASS는 여전히 사람 승인 뒤에만 나오게 한다(D53).
