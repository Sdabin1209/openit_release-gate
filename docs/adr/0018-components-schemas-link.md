# ADR-0018: 영역 구조를 컴포넌트·스키마·wiring으로, 통신은 openit_link 위에

- 상태: 채택
- 날짜: 2026-10-30
- 대체: 없음(ADR-0013의 HTTP 서빙 선택은 그대로, 그 위의 앱 구현만 바뀐다)

## 맥락

코드가 한 패키지의 평평한 모듈 열두 개였고, 모듈끼리 서로의 클래스를 직접 가져다 썼다(예: 판정 엔진이 검사·보고서·저장소를 직접 구성, 저장소가 보존 규칙을 가져다 씀). 거부 조건이 코드 곳곳의 `if`·`raise`에 흩어져 있어 "무엇을 받아들이나"를 한곳에서 볼 수 없었다. 헤드가 영역 설계 규칙을 정했다(D117, 구조 규칙 6개 D104).

## 결정

- 일을 업무 단계로 나눠 컴포넌트마다 파일 하나(`components/`), 입출력 타입마다 JSON Schema 하나(`schemas/`)를 둔다. 연결·주입은 `wiring/`, 코드 타입은 스키마에서 생성한다(`types/`).
- 컴포넌트는 서로를 가져오지 않는다. 저장소·시계·묶음 검증·이웃 읽기는 wiring이 넣는다. 받아들이는 조건은 스키마에 적고 컴포넌트는 `validate`로 입력을 검사한다.
- 이웃 통신은 `link_*` 컴포넌트만 한다. 받는 쪽은 통신 기반 라이브러리 `openit_link`(D118) 위에서 경로 표만 적는다.

## 왜

- 근거: functional core, imperative shell(Gary Bernhardt), 포트·어댑터(Alistair Cockburn), 구조 규칙 6개(D104)와 영역 설계 규칙(D117). 계약 HTTP 규약을 영역마다 다시 구현하면 어긋난다는 헤드의 판단(D118).
- 타입 생성에 `typing.TypedDict`를 고른 이유: 컴포넌트가 JSON 레코드(dict)를 그대로 주고받으므로 타입 힌트만 있으면 되고, pydantic을 런타임 의존으로 들이지 않는다.
- `types/validators.py`(스키마 묶음)도 생성물로 둔 이유: 컨테이너에는 `schemas/` 폴더가 없고 패키지만 들어간다. 사본이 어긋나면 `scripts/gen_types.py --check`(시험)가 실패한다.
- 저장소 세 구현을 한 파일(`registry_store.py`)에 둔 이유: PostgresStore가 번들 파일 처리(ReleaseFiles)를 SqliteStore와 함께 쓴다. 컴포넌트끼리 가져오지 않으므로 둘로 쪼개면 코드를 복사하게 된다. 한 컴포넌트(저장소)의 구현 셋이라는 해석이다.
- 토큰 종류를 역할 이름에 접두사(`r:`, `w:`)로 붙인 이유: `openit_link`는 토큰을 역할 하나로만 안다. 같은 역할 이름이 읽기·쓰기 토큰 양쪽에 있어도 읽기 토큰으로는 쓸 수 없어야 한다(CONVENTIONS 9절, 기존 시험이 요구).
- 쓰기 시도 기록은 `openit_link`에 훅이 없어 `link_http_server`의 얇은 껍질이 한다(변경 요청 `docs/change-requests/CR-0011`). 번들 tar는 v0.2.0의 bytes 반복자 스트리밍으로 흘린다.

## 검토한 대안과 버리는 이유

- 클래스 구조 유지 + 폴더만 이동: 컴포넌트끼리 직접 가져오는 의존이 그대로 남는다. 버림.
- 컴포넌트마다 pydantic 모델로 검증: 런타임 의존이 늘고 계약 검증(jsonschema)과 이중이 된다. 버림.
- 라이브러리 없이 기존 app.py 유지: 401/403·413·계약 검증을 영역이 다시 구현한다(D118이 금지). 버림.

## 결과

- 얻는 것: 입력·출력과 받아들이는 조건이 한곳(`schemas/`)에 있고, 구조 규칙이 시험(`tests/test_structure.py`)으로 강제된다.
- 감수하는 것: 파일 수가 늘고, 검사마다 입력 검증이 있어 호출당 비용이 조금 는다(측정 안 함). 405 응답 본문이 라이브러리 형식이 된다.

## 되돌리는 조건

- `openit_link`가 후처리 훅을 지원하면 껍질을 줄인다. 스키마 검증 비용이 문제로 측정되면 성능이 중요한 경로만 한 번 검증으로 줄인다.
