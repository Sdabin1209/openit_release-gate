# ADR-0019: 시간은 주입한다 (컴포넌트는 시계를 읽지 않는다)

- 상태: 채택
- 날짜: 2026-10-31
- 대체: 없음 (ADR-0008의 값은 그대로, 시험 방식만 바뀐다)

## 맥락

시간을 재거나 기다려 판정하는 시험(예: "1MiB 본문을 보내며 상태 줄을 읽는다", "끊기까지 25초 안", "docker pause로 DB를 얼려 5초 안에 UNAVAILABLE")이 기계 부하에 따라 결과가 갈렸다. 그런 시험은 실패해도 결함이 아니고 통과해도 옳다는 뜻이 아니다. 시험 중 실제 시간을 기다리거나 재서 판정하는 곳이 0이어야 한다(헤드 지시 U422).

## 결정

- 우리 코드의 시간(우리가 정한 마감·유예·타이머·합류 대기)은 **시계를 인자로 받는다**. 시계는 `monotonic()`, `sleep(초)`, `now()`, `epoch()`, `join(스레드, 초)`, `timer(초, 함수, 인자)` 모양이고 실제 구현 `SystemClock`은 `wiring/util.py`에만 있다. 컴포넌트(`link_http_server`의 우아한 종료·/readyz 합류·시도 기록 시각, `registry_store`의 문장 감시 타이머·확인 합류·임시 디렉터리 정리의 기준 시각)는 시간을 직접 읽지 않는다.
- 시험은 가짜 시계(`tests/conftest.py FakeTime`)를 넣고 시간을 직접 흘린다. 판정은 결과(남은 요청 수, UNAVAILABLE, 재시도 여부, 타이머 간격·취소)다.
- 라이브러리 안의 시간(waitress 연결 시한, PostgreSQL statement_timeout, psycopg 접속 시한, OS 신호)은 시험하지 않는다. 넘기는 값이 맞는지와 가짜 의존이 즉시 시간 초과·연결 실패를 던질 때의 우리 결과만 확인한다.
- 남는 대기는 시험이 자기 가짜에게서 신호를 기다리는 것뿐이고 마감은 상수 하나 `HANG_GUARD_SECONDS`다(매달림 감시). `tests/test_no_real_time.py`가 정적으로 강제한다.

## 왜

- 표준 관행: 의존성 주입으로 시계를 바꿔 끼운다(Clock 인터페이스, 가짜 시계). 시험 가능한 설계의 일반 원칙이다.
- 근거: 흔들림의 원인이 시험이 시간 자체를 판정에 쓴 것이었다. 시계를 주입하면 시간 의존이 시험 코드의 통제 아래로 들어온다.

## 검토한 대안과 버리는 이유

- 전역 시간 patch(freezegun, `time.sleep` monkeypatch): `Event.wait(timeout)`, 소켓 timeout, `Thread.join(timeout)` 같은 **블로킹 대기**를 움직이지 못한다(실제 시간이 흐르기를 기다린다). 우리 코드의 마감 대부분이 이런 대기라 버렸다.
- 마감 값을 키워 덜 깨지게 하기(U420): 덜 깨질 뿐 고친 것이 아니다. 판정이 여전히 속도에 달린다.
- 실제 시간 시험을 유지하고 반복으로 확인: 안전하다는 증거가 못 된다.

## 결과

- 얻는 것: 시험이 부하와 무관하게 같은 결과를 내고, 느린 시험(유예·시간 초과를 실제로 기다림)이 사라져 전체 시험이 빨라진다.
- 감수하는 것: `GateApp`/`GateHTTPServer`가 `clock` 인자를 필수로 받는다(기본값으로 실제 시계를 읽지 않는다). `PostgresStore`는 `scheduler`(기본은 시간을 읽지 않는 표준 타이머·합류), `purge_stale_tmp`는 `now`를 받는다. 와이어 형식·HTTP 응답·잡 출력은 그대로이고, 전체 시험(적합성, HTTP, 잡)으로 확인했다.
- 지운 시험의 실제 동작(waitress가 느린 연결을 끊는지, DB 얼림, SIGTERM)은 smoke·E2E의 몫이다(`tests/TIMING.md`).

## 되돌리는 조건

- 시계 주입이 영역의 설계를 해칠 정도로 번지면(주입할 자리가 계속 늘면) 시간 사용을 한 컴포넌트로 모으는 방향으로 다시 정한다.
